# 리루프 · 스마트 분리수거 관리 MVP

대회 시연을 위한 관리자 웹 애플리케이션입니다. 실물 쓰레기통 1대의 센서 연결과 3층 더미 건물의 수거 경로를 함께 보여 줍니다.

## 시작하기

1. `실행하기.cmd`를 더블 클릭합니다.
2. 브라우저에서 `http://127.0.0.1:8765`가 열립니다.
3. **시연 계정으로 둘러보기**를 누릅니다.

시연 계정은 `demo@reloop.local` / `Demo1234!`입니다. 회원가입으로 만든 계정은 각각 독립된 건물 데이터를 갖습니다. 실제 이메일 전송이나 외부 인증 서비스는 사용하지 않습니다.

- 실행 환경: Windows, Python 3.10 이상. GitHub에서 처음 받은 소스를 실행하거나 화면을 다시 빌드하려면 Node.js 20.19 이상이 필요합니다.
- GitHub 저장소에는 소스 코드가 포함됩니다. 첫 실행 시 `dist/`가 없으면 실행기가 화면을 자동으로 빌드합니다.
- 배포 ZIP에 포함된 `dist/`를 사용하는 일반 실행에는 Node.js가 필요하지 않습니다.
- 첫 실행 시 Python 의존성이 없다면 `.venv/`에 설치합니다. 설치가 끝난 뒤에는 인터넷 연결 없이 사용할 수 있습니다.
- 서버는 숨겨진 창으로 실행되며, 브라우저를 닫아도 계속 동작합니다.
- 종료하려면 `종료하기.cmd`를 실행합니다. 데이터는 유지됩니다.
- 시작 오류는 `logs/server.err.log`에서 확인합니다.

PowerShell에서 실행할 수도 있습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

GitHub에서 내려받은 경우 압축을 먼저 풀거나 저장소를 복제한 뒤 프로젝트 폴더의 `실행하기.cmd`를 실행하세요. 최초 의존성 설치에는 인터넷 연결이 필요합니다. 계정·센서값·도면·수거 기록은 저장소에 포함하지 않으며, 실행한 PC의 `data/`에 새로 만들어집니다.

## 기본 구성

| 항목 | 내용 |
| --- | --- |
| 건물 | 3개 층, 층마다 쓰레기통 4개 |
| 실물 | B-001. 연결 전에는 적재율을 비워 두고 수신 대기로 표시 |
| 더미 | B-002~B-012. 카드에서 적재율 조절 가능 |
| 관리자 | 전체 3명, 수거 가능 2명으로 시작. 0~전체 인원으로 조절 |
| 관리자실 | 1층. 모든 관리자 경로의 출발·복귀 지점 |
| 정상 | 80% 미만, 초록 |
| 주의 | 80% 이상~90% 미만, 주황 |
| 수거 필요 | 90% 이상, 빨강 |
| 기본 경로 | 빨강만 포함. ‘주황색 쓰레기통도 포함’ 선택 가능 |
| 새로고침 | 5초 간격. 화면이 백그라운드이면 일시 중지 |

상태 기준은 설정에서 변경할 수 있습니다. 실물 센서가 5분 이상 최신 측정을 보내지 않으면 회색으로 표시하고 자동 경로에서 제외합니다.

## 권장 시연 순서

1. 시연 계정으로 로그인합니다. 층별 쓰레기통 번호와 적재율을 설명합니다.
2. **수거 경로 계산**을 누릅니다. 빨간 쓰레기통 3개가 배정되는 것을 확인합니다.
3. **주황색 쓰레기통도 포함**을 선택합니다. 수거 대상이 6개로 늘어납니다.
4. 동일한 상태에서 수거 가능 인원을 1명, 2명, 3명으로 바꿉니다. 관리자별 담당 목록과 예상 완료 시간이 바뀝니다.
5. 지도에서 1F·2F·3F를 전환하고 관리자별 경로를 선택합니다. 지도 안의 작은 숫자는 해당 관리자의 방문 순서입니다.
6. **장치 연동**에서 실제 센서값을 받거나, ‘실물 위치 시뮬레이션’을 96%로 적용합니다. 시뮬레이션은 실제 센서와 별도로 표시됩니다.
7. 경로를 다시 계산합니다. 입력 상태가 변경된 기존 경로에는 재계산 안내가 표시됩니다.
8. 담당 쓰레기통의 **수거 완료**를 누릅니다. 남은 경로가 갱신되고 **수거 기록**에 저장됩니다.

‘시연 시나리오’에는 일반적인 하루, 점심시간 이후, 수거를 마친 건물이 있습니다. 시나리오는 더미 쓰레기통만 변경합니다.

다음 시연 전에는 설정에서 **시연 데이터 초기화**를 선택할 수 있습니다. 현재 계정의 배치와 수거 기록이 초기화되므로, 보관할 데이터는 먼저 백업하세요.

## 배치 편집

- **건물·배치도**에서 건물 이름과 층수를 저장합니다.
- ‘쓰레기통’ 도구를 선택한 뒤 지도 위를 클릭하면 더미 쓰레기통을 추가합니다.
- ‘관리자실’ 도구로 출발·복귀 장소를 지정합니다.
- ‘선택·이동’에서 쓰레기통, 관리자실, 통로 지점을 드래그합니다. 쓰레기통과 관리자실 이동은 바로 저장됩니다.
- 통로의 추가·이동·삭제는 **통로 저장**을 눌러 적용합니다.
- 쓰레기통은 같은 층의 연결 통로를 선택해야 합니다. 이 통로에서 해당 위치로 직접 접근할 수 있도록 배치하세요.
- 층 사이에는 계단끼리 또는 엘리베이터끼리 연결합니다. 층간 연결의 기본 거리는 층당 12m이며, 실제 거리를 입력할 수 있습니다.
- 도면은 PNG·JPG·WEBP, 최대 4MB입니다. 업로드한 도면의 벽이나 복도를 자동 인식하지 않습니다. 통로는 직접 지정합니다.
- 도면 좌표는 가로·세로 각각 0~100입니다. 기본 축척은 1단위=0.6m입니다. 실제 도면은 설정에서 축척을 조정합니다.
- 제거할 층에 쓰레기통, 관리자실 또는 통로가 있으면 먼저 다른 층으로 옮기거나 삭제해야 합니다.

## 수거 동선 계산

1. 최신 상태에서 빨강, 또는 빨강+주황 대상을 선별합니다.
2. 관리자실·통로·계단·쓰레기통으로 연결 그래프를 만듭니다.
3. 다익스트라 알고리즘으로 장소 사이의 최단 이동 거리를 계산합니다.
4. 먼 대상을 먼저 배정하면서 전체 작업의 예상 종료 시간을 줄이는 위치에 삽입합니다.
5. 방문 순서 뒤집기(2-opt)와 관리자 사이의 작업 이동으로 경로를 개선합니다.

여러 관리자의 배정은 근사 추천 방식이며 전체 최적해를 보장하지 않습니다. 예상 시간은 `이동 거리 / 보행 속도 + 쓰레기통 수 × 1개 수거 시간`입니다. 기본값은 1m/s, 쓰레기통당 45초입니다. ‘전체 완료 예상’은 가장 늦게 끝나는 관리자의 예상 시간입니다. 관리자 수가 늘면 총 이동 거리는 늘어날 수 있습니다.

관리자 0명, 수거 대상 없음, 끊어진 통로, 관리자실과 연결되지 않은 쓰레기통은 각각 별도로 표시합니다. 실제 인력 추적이나 자동 출근 감지는 없으며, 수거 가능 인원은 시연자가 직접 입력합니다.

## 실물 센서 연결

1. **장치 연동 → 장치 연결 키 발급**에서 키를 생성하고 장치 설정에 복사합니다.
2. 센서나 게이트웨이가 아래 요청을 보냅니다.

```http
POST /api/device/readings
Content-Type: application/json
X-Device-Key: 발급한_장치_연결_키
```

```json
{
  "bin_id": "B-001",
  "fill_percent": 94
}
```

`fill_percent`는 0~100의 숫자입니다. `measured_at`에 시간대가 있는 ISO 8601 측정 시각을 추가할 수 있습니다. 예: `2026-10-30T10:30:00+09:00`. 생략하면 서버 수신 시각을 사용합니다. 이미 처리한 값보다 오래된 측정은 거절합니다.

연결 키는 발급한 계정의 실물 장치에만 적용됩니다. 키를 다시 발급하면 이전 키는 만료됩니다. 키 원문은 데이터베이스에 저장하지 않습니다.

실물 값을 수신하면 시뮬레이션 표시가 자동으로 실제 센서 표시로 바뀝니다. 실물 장치의 수거 완료는 측정값을 임의로 0으로 만들지 않습니다. 다음 센서 측정으로 실제 비워진 상태를 확인합니다.

센서 전송 테스트용 도구도 제공됩니다.

```powershell
python tools\send_reading.py --fill 94
```

실행 후 연결 키를 입력합니다. 이 도구의 테스트 패킷은 실물 수신 경로로 들어가므로 대회 발표에서는 테스트 입력과 실제 센서 측정을 구분해 설명하세요.

다른 기기의 센서를 연결하려면 서버를 종료한 뒤 LAN 모드로 다시 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Lan
```

센서의 전송 주소는 `http://서버PC의IP:8765/api/device/readings`입니다. 기존 서버가 실행 중이면 모드가 바뀌지 않으므로 먼저 `종료하기.cmd`를 실행합니다. 같은 사설 네트워크에서 통신할 수 있어야 합니다. 기본 실행은 이 PC에서만 접속할 수 있습니다.

## 저장 및 백업

- 데이터베이스: `data/reloop.sqlite3`
- 업로드 도면: `data/maps/`
- 저장 내용: 계정, 건물 설정, 위치, 통로, 적재율, 수거 기록, 최근 수신 기록, 마지막 경로
- 계정 비밀번호: 무작위 소금값과 PBKDF2-SHA256으로 저장
- 로그인 세션: HttpOnly·SameSite 쿠키, 만료 7일
- 계정마다 워크스페이스가 분리됩니다.
- 설정의 백업 다운로드는 건물·도면·운영 기록을 내보냅니다. 비밀번호·세션·장치 키는 제외됩니다.
- 복원 후 실물 장치는 새로운 측정을 기다립니다. 백업의 과거 실물값을 현재값으로 사용하지 않습니다.

이 앱은 대회용 로컬 MVP입니다. 실물 장치의 펌웨어·게이트웨이는 위 전송 형식에 맞춰 별도로 연결해야 합니다. 서버 수신 기능과 모의 패킷 동작은 검증할 수 있지만, 실제 센서의 정확도나 무선 연결 품질은 해당 장치로 현장 확인이 필요합니다.

## 개발 및 검증

```powershell
npm ci
npm run build
python -m pytest tests -q
```

개발 중에는 `python -m uvicorn server.app:app --host 127.0.0.1 --port 8765`와 `npm run dev`를 별도 터미널에서 실행합니다. Vite 화면 주소는 `http://127.0.0.1:5173`이며 API는 로컬 서버로 전달됩니다. 일반 시연에서는 미리 빌드된 화면과 API를 8765 포트 하나로 제공합니다.

구성: React + TypeScript + Vite / FastAPI / SQLite. 외부 로그인, 지도 서비스, 클라우드 저장, 외부 폰트에 의존하지 않습니다.
