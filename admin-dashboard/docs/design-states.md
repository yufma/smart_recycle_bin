# 디자인 적용과 상태 점검 — 2026-11-02

## 구현한 흐름

| 발생 조건 | 화면에서 보이는 내용 | 다음 행동 |
| --- | --- | --- |
| 실물 센서 첫 수신 전 | 연결 대기, 측정값 없음, 칸별 수신 대기 | 장치 연동 |
| 일부 칸만 유효함 | 최신 칸만 표시, 일부 칸 수신 안내, 상세에 이전 기록 | 센서 연결 상태 확인 |
| 필터 결과가 비어 있음 | 선택한 조건에 해당하는 쓰레기통이 없다는 안내 | 전체 쓰레기통 보기 |
| 경로 계산 중 | 처리 중 표시, 중복 요청 방지, 진행 상태 안내 | 응답 후 같은 조작 요소로 키보드 초점 복귀 |
| 센서·배치·운영 조건이 바뀜 | 이전 경로선·수거 순서·예상 시간 숨김 | 경로 다시 계산 |
| 수거 가능한 관리자 0명 | 배정할 수 없다는 안내 | 관리자 1명으로 계산 |
| 한 위치가 운반 용량 초과 | 대상 번호와 필요량·허용량, 빈 경로 | 운반 용량 설정 확인 |
| 수거 대상 없음 | 수거할 곳이 없다는 안내 | 상태가 바뀌면 다시 계산 |
| 저장·계산 실패 | 지속되는 오류 안내와 오류 알림 | 최신 정보 다시 불러오기 |
| 응답이 30초를 넘김 | 대기 해제, 반영 여부를 확인하도록 안내 | 최신 정보를 확인한 후 재시도 |
| 연결 끊김 | 마지막으로 받은 데이터라는 배너 | 서버 실행 후 다시 연결 |
| 대화상자 열기·닫기 | 배경 조작 차단, Tab 순환, Escape 닫기 | 열었던 버튼으로 복귀 |

시연 시나리오와 수거 완료는 서버가 경로를 자동으로 다시 계산할 수 있다. 이 경우에는 정상적인 최신 경로를 표시한다.
타임아웃은 요청이 서버에 반영되지 않았다는 뜻이 아니므로 수거 완료·저장 요청을 자동 재전송하지 않는다.

## 확인 방법

- `npm run build`: 타입 검사와 화면 빌드.
- `npm run test:client`: 요청 성공, 오류 상세, 로그인 만료, 연결 실패, 타임아웃, 자동 재전송 방지.
- 브라우저: 데스크톱과 390px 모바일 화면, 주황색 포함, 키보드 계산 방식 선택, 빈 필터 복구, 관리자 0명 복구, 용량 초과 안내, 오래된 경로 숨김, 일부 칸 수신, 저장 오류, 서버 연결 끊김과 재연결, 팝업 초점 순환과 복귀.
- 실행 중 사용자 데이터 대신 별도 시연 데이터 폴더로 점검한다.

공통 디자인 값과 적용 원칙은 [디자인 기준](../../.interface-design/system.md)에 기록했다.
